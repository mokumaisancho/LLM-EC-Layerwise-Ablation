# GEN001 — 4状態モデルの入力インターフェースと計算削減主張の細粒度監査

Date: 2026-11-07 / [PoC7 source](poc/poc7_lstar_fallback.py) / [PoC7 evidence](poc/POC7_OBSERVED_SUMMARY.json) / [汎用判断スキル](../../.agents/skills/evidence-to-next-action/SKILL.md)

**結論**：PoC7は固定resetと操作履歴から利用できる4状態の**振る舞いモデル**を学習した。任意の128-bit raw状態に対する投影 `phi(x)` を学習したわけではない。固定resetワークロードでは、**元の到達可能raw状態数そのものが4であり、学習後の4状態モデルへ到達可能状態数の縮約は観測されない**。一方、元表現の幅・元処理の計算操作・潜在的な全状態と、到達可能状態数は別の量。

## A. 何の情報を処理しているか（層ごとの境界）

| 層 | 入力 | 実行される操作 | 出力 | このPoCの事実 |
|---|---|---|---|---|
| A0 元システム | `x`: 128bitを表現できるPython整数 / 操作a | `NonlinearScrambledSUL.step(x,a)` | 次の元状態`x'` | 実装あり |
| A1 観測 | 元状態 `x` | `output(x)` | 1bit出力 `y` | 実装あり |
| A2 学習 | 既知resetからの操作列 → 観測列、反例探索 | L*観測表の更新 | 4状態の遷移・出力表 | PoC7で学習・到達可能検算 |
| A3 既知履歴の利用 | 学習モデルの初期状態と既知操作列 | 学習した表の逐次遷移 | 未来の`y` | この用途では`phi(x)`不要 |
| A4 新しい任意raw状態の利用 | 新しい`x` | **`x→学習モデルの状態` を決める処理** | 学習モデルの初期状態 | **学習器には未実装** |
| A5 性能比較 | 同一契約のraw処理と学習モデル | 同じ未来観測を生成し総費用比較 | 適用範囲付きの便益 | **同等の適切な直接対照が不足** |

**混同禁止**：A2は「入出力モデルの発見」、A4は「新しい生入力の投影／対応付け」、A5は「計算資源の改善」であり、別々の主張。A2のPASSだけでA4/A5をPASSにしない。元SULが内部に持つ `to_latent` は学習器が見つけた `phi` ではない。

## B. 今回実行した最小の静的＋到達可能性チェック

PoC7ソースの非線形合成系 `NonlinearScrambledSUL(n=128, initial=0, actions=(0,1))` の `to_latent/from_latent/step` と同じ算式を使い、幅128bitのBigIntを扱って到達可能な元状態を列挙した。

| 元raw状態（hex） | 元コード内の2bit latent q | hidden h |
|---|---:|---:|
| `0x0` | 0 | 0 |
| `0x2` | 1 | 0 |
| `0x3` | 2 | 0 |
| `0x1` | 3 | 0 |

- reset=0、操作0/1を全組合せで何度繰り返しても、到達可能なraw状態はこの**4個**。全て`h=0`。4状態の学習モデルも**4状態**。実験ワークロードの状態数は4→4である。
- 理論上の潜在状態`2^128`は定義域の可能数であり、**この操作契約で実際に探索した状態数ではない**。
- 128bit幅の整数を使えることと、実際に各遷移で128bitの多様な状態情報を処理する必要性は異なる。値は常に0〜3の範囲。
- 合成SUL内の `to_latent` は一般の非ゼロhiddenのraw入力からqを計算可能だが、**L*がこの任意raw入力の`phi`を学んだ証拠ではない**。将来の操作が新しいhiddenやresetを許せば証拠スコープを更新する。

## C. このモデルが何を可能にするか（利用条件を先に固定）

**C1: 固定reset＋操作履歴の継続予測**：学習モデルの初期状態を使い、許可操作から観測を予測できる。追加raw投影なし。PoC7実行済み。

**C2: 任意rawスナップショットから予測**：最初にraw`x`から学習モデルの状態を決める対応表または`phi`が必要。現行の学習成果は**これを提供しない**。C1とC2を同じ高速化実験に混ぜない。

**C3: 投影による演算削減**：変換費用と、元の最も単純な直接実行法を含む比較が必要。ソースを一般的な128bit元状態として扱う場合、直接最適化した低次元規則やメモ化の対照を省略しない。PoC7の約18倍のraw Python差は、重い `to_latent/from_latent` を含む元実装対テーブル参照であり、**学習アルゴリズム固有の速度優位を示さない**。

## D. 本線の単一の次の判断（無駄なPoCを防ぐ）

**先に決めるべきこと**：どの入力契約を評価しているか。既存PoC7の実際の契約は固定reset＋既知操作履歴なので、まずC1を基準にする。未知raw入力の任意射影C2は、この実験には不要。

**最小の未検証接続点**：既知resetワークロードで「学習して作った4状態テーブル」が、**既に分かっている2bitの直接更新規則**または単純キャッシュと比較して独自の価値を持つか。

次の小作業は、学習済みモデルを新たに作り直すことでも、一般推論を試すことでもない。まず**直接2bit規則を比較対照として固定し、その1ステップ更新の操作と出力が、学習テーブルと等価かを確認する**。ここで同じなら、元の重い128bit wrapperとの速度比だけを「投影の価値」とはできない。**この確認後に限り**、学習・検証・初期変換・反復更新の費用と利用回数別損益分岐を測る。

- 判定PASS：同じ入力契約でどちらも正しく、必要な反復・計算条件が定義できる。ここでのPASSは対照が成立したことのみ。
- 判定FAIL：直接規則・モデルの出力差があり、前提または実装を訂正。
- 判定UNKNOWN：同じ契約で比較できず、欠けた入力を特定。

**保留**：未知の新しい目標への計画、一般化、ECv4.4への追加接続、任意のraw状態への`phi`学習。これらを必要とする現実の入力条件・反例が示された場合に限り着手する。

**現在の監査ステータス**：固定resetでraw到達状態が4個と確認済み。直接2bit更新規則との独立対照の性能比較は**NOT_RUN**。従来の「総費用損益分岐を直ちに計測する」提案は、比較対照を固定するまで保留。
