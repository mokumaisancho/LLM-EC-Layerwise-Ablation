## 1. 原課題と従属する一つの判断

原課題は「巨大な既存LLMを出発点にせず、最小の構造・規則・表現からどの程度の推論が成立するか」。C6で費用改善を確認したのは**元の遷移法則が既知**のGF2系に限る。

次の判断は「既知sourceのP4に対し、source-hiddenのk0 L*はなぜraw状態→抽象状態の`phi`を持たないか。どの観測が追加されれば、最も小さな接続が成立するか」。

### 正確な3つの情報アクセス条件

| 情報アクセス | 既存で成立する能力 | raw状態の初期化に使える`phi` | 判定 |
|---|---|---|---|
| A: 固定reset、操作列→最後の出力1bitのみ | L*が4状態の予測機械を取得し、履歴から将来を予測 | **識別不能**（rawラベルへの接点が一切ない） | 既存k0 L*で予測PASS。raw mapperは不可能 |
| B: A + **操作列から到達した生状態IDのスナップショット** | 以前の学習機械の状態IDと、生状態IDを同じ履歴で関連付け、到達集合の対応表を構築 | 今回の合成8bitに限り256要素の全域対応表を作成できる | 今回限定PASS |
| C: B + XOR投影クラスを前提として、複数のraw遷移先を観測 | 過去P3の既存探索器で、2マスクによる小さな数式候補を探索 | 線形クラス内の候補が既に実測済み。未知の任意非線形規則を表現できる保証なし | 既存P3を**REUSE**、新規探索器不要 |

**Aの予測用途では`phi(raw)`自体が不要**（resetから既知の操作履歴でモデル状態を追える）。任意のrawスナップショットから予測したい用途B/Cで初めて欠ける入力となる。用途を問わず`phi`をP0と扱わない。

## 2. 実行した一つの最小実験

MGR-P1の元8bit合成系`k=0`（[原コード Git blob `9167e7e...`](poc_finite_quotient_v1/run_poc.py)）と、すでに学習・検証済みのL*の4状態遷移表（[証拠 `K0_FIXED_RESET...`](poc/K0_FIXED_RESET_BLACKBOX_OBSERVED_2026-11-07.json)）を**変更せず再利用**。

学習側の取得機能を、既存の`word→out`から`word→(raw_snapshot,out)`に**一種類だけ拡張**。rawは8bit状態の識別子で、元内部`phase`、`noise`、`step`の数式は学習側へ渡さない。固定reset=0からBFSし、履歴を再生することで`raw→learned_state_ID`を作る。

| 計測 | 実際の結果 |
|---|---:|
| raw状態に対応付けた件数 | 256/256 |
| 学習モデルの状態数 | 4、各64件 |
| snapshot問い合わせ | 513（reset1 + 2×256遷移） |
| resetからの操作再生 | 4,160回 |
| 最大に必要だった履歴長 | 11操作 |
| 既存モデルへの整合確認 | 512/512遷移 |
| 学習終了後のsource-aware checker | 256出力＋512遷移 PASS |
| 故意にrawラベルを取り違えさせる負例 | 操作列`[1]`で**RAW_ID_CONFLICT**を検出 |

**証明の範囲**: もともと初期raw0から全256状態に到達できる既知合成系なので、全状態を観測できる。新たに元raw状態が観測可能だというインターフェースを与えたこと自体が強い前提であり、元のAのL*学習成果から無償で得られた情報ではない。snapshotラベルを偽装した場合、常に識別できるわけではない（今回の衝突負例1件のみ検出）。

## 3. 「出力だけからraw座標を復元」は理論的に不識別

全raw状態の名前を入れ替える写像`p`のうち、reset raw0を固定し、raw1とraw2を交換するものを構成。`T'=p∘T∘p⁻¹`、`O'=O∘p⁻¹`とすると、任意の操作列wについてresetからの出力は同一になる（長さに関する帰納法）。一方、rawラベル1に対する現在出力は元系0、入替系1となり、要求されるraw→モデル状態への対応は異なる。

- 長さ0〜8の**511操作列**の出力が全一致することを実際に照合。全系列の同値性は上記の状態の名称変更に関する帰納法。
- どんなに優れたoutput-only学習器でも、この2候補を出力列から判別できない。**この入力条件から一意のrawラベル射影を要求すること自体が不適切**。
- また、同じ振る舞いを持つ4状態の**名前の付け方も任意**であり、数学的に一意な特定の座標名の復元を成功条件にしない。

## 4. 重複する新規実装を避ける

過去の[P3部分観測XOR探索](poc_finite_quotient_v1/sparse_discovery_results.json)は、**raw状態と各操作後のraw遷移先が観測できる**条件で、2つのGF2 parityマスクを候補探索する。k=0に対して12 raw標本×10シードの独立全状態照合は10/10 PASS、8標本では3/10誤PASS。候補`(0x03, 0xfd)`はこの8bit合成系の未来出力を保存する。

- 今回取得した256元状態と512操作辺は、既存P3に要求される入力をすでに含む。
- P3のXOR候補は、学習済み4状態の**状態番号と同じ値である必要はない**。2bitの座標と学習機械の状態IDの間に一対一のrenameがあればよい。
- **P3のアルゴリズムを再発明しない**。別の発見手法を作るのは、同一入力契約でP3が反例を示した場合のみ。
- ただし「P3が今回のsnapshot datasetから新たにcompact phiを実行生成した」という接続E2Eの完了は、実際にその統合作業を行うまで主張しない。

## 5. 現在の意思決定と停⽌条件

**判断：REUSE。** 原課題への新たな知見は「出力だけでのraw射影の不識別性」と、「raw snapshotの一種類の追加で既存の到達256状態すべてに対応付けられる」という接点。**未知規則の一般的発見や新しい推論能力が成立したという主張はしない。**

次に必要なのは、用途が実際に`任意raw→抽象予測`を要求するのか、その場合に**既存P3を利用できる表現クラス**が十分かを見極めること。固定resetの出力予測しか要らなければ、raw`phi`導入を強制せずL*成果を利用する。k=1では未来等価状態が6となり、2bit XOR候補の制約では全域を表現できないことも既存P1/P3で確認済み。
